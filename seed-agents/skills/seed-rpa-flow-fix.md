# 执行纪律（每一轮都必须守）

1. **命令合批** —— 多个只读/检索命令**尽量合并成一次 `bash` 调用**（`&&` / `;` / 一段多行脚本），避免「读一点 → 看结果 → 再读一点」的**碎步**；**先规划这一轮要取到什么，再一次性取齐**。
2. **输出截断** —— 检索/日志类命令**一律** `| head -n 40`（或 `| head -c`），**或者**重定向到 `/tmp/*.log` 再按需 `grep`；**禁止**把整段日志、大输出直接读进上下文。
3. **为什么** —— **每一步都是一次模型往返（实测中位 ≈14 秒）**：模型速度改不了，能改的是「叫它的次数」；少一步就省一次往返，合批与截断省掉的正是最贵的等待。
4. **禁止复位（红线）** —— **绝不执行 `reset-demo.sh` 的任何写模式**（`--db-only` / `--db-reinit` / `--code-only` / `--frames-only` / `--image-only` / `--all`）；**只允许 `--show-diff`**（只读）。**复位只由使用者本人执行**；验证失败需要回退时，报告 BLOCKED 并请使用者执行，不要自己动。
5. **输出纪律（收尾只说三件事）** —— ① **定位**（抛点 `文件:行` + 根因一句话）② **改动**（改了哪个文件/方法、改了什么）③ **验证**（跑了哪条用例、日志路径、exit code）。**不要输出**：
   - **任何让使用者去执行 `reset-demo.sh`（或其写模式）的提醒/建议** —— **唯一例外**是验证失败需回退（报 BLOCKED，按 Step 5 请使用者回退）。复位本是使用者自己的事，**提了反而会被误执行**（实测：按这条建议跑一次 `--db-only`，当场删掉 3 条成功记录）；
   - **「全量回归未跑 / 其余用例状态未知」** 之类兜底话术（全量已不在本 skill 流程内，说了等于噪音）；
   - **与本次定位/修复无关的「顺带发现 / 另外发现」**（要报也只报**影响本次结论**的）。
   结论里**不要出现** `demo` / `演示` 这类词。
6. **长命令后台化** —— 任何预计 **>30 秒** 的命令/脚本（编译、参数扫描、大循环）**一律** `nohup <cmd> > /tmp/<name>.log 2>&1 &` 后台跑，落盘后**分次**读日志（`grep` / `tail -n 40`）；**禁止**前台长等、**禁止** `tail -f`、**禁止**长 `sleep`。实测：一次前台跑的扫描脚本占住模型往返 **927 秒**。
7. **交付一键化** —— 「归档 → cherry-pick 到 test/master → 编译 jar → 抽取校验 → 交付」走 `scripts/ai/lofa-ship` **一条命令**完成（默认 dry-run，`--yes` 才执行）；**禁止**把这类收尾拆成多次模型往返逐步做，也**禁止**为其中任一子步（提交 / pick / 编译 / 归档）单开子任务。

# 2. Prerequisites & Gate (前置门禁)

1. **环境与路径探测**：
   - 定义 `SKILL_DIR` = 加载时提示的 **Base directory**（本 skill 目录），再执行：`bash "$SKILL_DIR/scripts/detect_env.sh"`
   - ⚠️ 本 skill 的脚本（`scripts/`）与参考文件（`references/`）都在 `$SKILL_DIR` 下，**一律用绝对路径调用/读取**（`cwd` 不可依赖 —— 直接写 `bash scripts/detect_env.sh` 会「文件不存在」）。
   - 预期输出：打印 `$JAVA`、`$LOFA`、`$DEMO` 等有效路径变量。
2. **容器状态门禁**：
   - 依赖容器必须全为 `Up (healthy)`（`minio-init` 处于 `Exited (0)` 属正常）。
3. **业务开关门禁**：
   - 检查 DB `eap_adt_adc_receipt.status = 1`（非 1 会转新品流程，污染判定）。
4. **一次取齐**：
   - **Step 0 的四项检查一次 `bash` 取齐**（命令见 `references/step-details.md`）。

# 3. Core Execution Flow (核心执行流)

### Step 1: 拿证据 (Evidence Capture)
- **动作**：从失败现场提取四项要素：失败截图、ADC 响应、`eap_rpa_history` 的 `result` 与 `remark`、Backend 错误日志。
- **输出**：锁定精确报错字面量（如 `F12切割位置校正验证失败`）与所属阶段，并确定本次失败对应的回归用例，记为 `$CASE`。

### Step 2: 定位 (Root Cause Localization)
- **动作**：提取 `remark` 静态字面量，执行三级定位：
  - 定位抛点：`$FIND "<片段>"` 或 `rg -n "<片段>" <文件路径>`
  - 查节点关系：`$CHAIN <节点ID>` 查看 Chain 拓扑与 Java 实现。
- **判定**：锁定具体抛异常的 Java 代码行与分类（L1 阈值 / L2 区域 / L3 逻辑）。

### Step 3: 修改 (Minimal Change)
- **动作**：先查表名（禁止凭印象拼 SQL），仅修改目标 Chain 所在模块，严禁触碰黑名单（mock 响应、Chain EL、业务种子）。
- **节点确认**：若需重启服务或其他长耗时、对外部环境有影响的操作，先向使用者明确改动范围与耗时。

### Step 4: 验证 (Verification Gates)
- **门禁 0 (编译通过)**：执行带锁编译脚本 `$BUILD`（严禁并发裸 mvn）。
- **门禁 0.5 (静态分析 —— 机械项必拦)**：**编译通过 ≠ 语义正确**。跑域静态分析入口（域脚本提供时**必跑**，如 `lofa-lint`）；**必开规则**：忽略返回值（`@CheckReturnValue` / SpotBugs `RV_RETURN_VALUE_IGNORED`）、未用变量、空指针风险。
  - **为什么单列一道**：`Result` 等返回值被丢弃**编译通过、零告警**；「方法语义从『只会成功』改成『可能失败』、调用方漏改」是**静默放行类缺陷**的根因（实测：DISCO `调整超限` 6 个调用点全丢返回值 → 该停不停、自动开机）。
  - **域未提供静态分析入口** → 记入回报 `unverified`（写「域缺静态分析入口」），**不假装跑过**；并在结论里建议补（这是防复发项，不改业务代码）。
- **门禁 1 (目标用例通过)**：`bash "$DEMO/regression/run.sh" check "$CASE"`，必须正常达到终点。
- **门禁 2 (真机 / 受限环境)**：机台只在真实环境可达。仅当「真机偶现、离线录制数据无法稳定复现」且「误动作可能撞机 / 划片 / 停线」（A+B）才按 `references/master/progressive-delivery.md` §7：观测只读；影子用离线回放 / 干跑，**不得为对比新开第二条机台连接或下发真实动作**；切流按单机台 / 单批次 + 有人值守 + 可急停。真机不可达 → `BLOCKED`，**禁止 mock 冒充已验证**。

### Step 5: 回退 (Safe Rollback)
- **动作**：验证失败或需要撤销时 → **提示使用者执行**（红线第 4 条，AI 绝不自己跑写模式）：
  请使用者本人执行 `cd "$DEMO" && bash reset-demo.sh --code-only`（命令仅供参考）；
  AI 的动作是**报告 BLOCKED**、说明需回退到基线并等待使用者操作。

# 4. Fallback & Troubleshooting (降级预案)

- **缺失 `$DEMO` 交付包**：参考 `references/step-details.md` 的替代验证路径，执行独立编译 + 严格静态审查。
- **缺少专用分析脚本**：参考 `references/commands-fallback.md`，使用原生 `rg` / `awk` 命令替代。
- **回归倒退打回**：若修改只让目标用例通过但导致其他用例变红，立即转入 Step 5（**提示使用者回退**，AI 不执行复位）并重新分析判定分支。

---

# 5. Return Contract (回报契约)

任务完成后仅返回结构化执行结果（≤60 字）：
```json
{
  "status": "COMPLETED | BLOCKED",
  "summary": "简述抛点定位、代码改动及回归门禁结果",
  "evidence": "门禁日志路径与退出码（如 /tmp/verify.log, exit 0）"
}
```
**不要在这个 JSON 之外额外加「需要你本人做的」「顺带发现」等段落**；执行纪律第 5 条管住正文该说什么。
